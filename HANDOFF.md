## 1. Что за проект и роль

Репозиторий **budni-crm** (Next.js App Router на Vercel, БД Neon + Prisma, Telegram-бот на grammy).
Внутри существующего AI-агента **Бориса** (`src/lib/boris/`) построена НОВАЯ РОЛЬ — **«трафик Яндекс.Директа»** (`src/lib/boris-direct/`). Это НЕ второй бот и НЕ новая личность: Борис один, его личность переиспользуется байт-в-байт.

**North star (дословно от владельца):** «при минимально возможных расходах в рамках цели достичь наибольшего результата с наибольшей эффективностью» = **МАКСИМУМ ЗАЯВОК на рубль** (не клики/охват). Оптимизация на цель Метрики «Заявка».

**Боевые объекты:** кампания `711897777` («Будни — Поиск — Волна 1», ручные ставки HIGHEST_POSITION, Network SERVING_OFF, DailyBudget 3000 ₽); группы G1/G2/G8/G4 = `5769314414..17`; счётчик Метрики `110272989`; цель «Заявка» `575665118`; чат Telegram «Директ от Бориса» `-5284101616`.

## 3. Итог полигона (детали — `sim/README.md`, `sim/SIM_LOG.md`)

Полигон гоняет РЕАЛЬНЫЙ мозг против симулированного мира (мокнут только 6 листовых транспортных модулей; предохранители работают по-настоящему). Прогон: `npm run sim:calibrate`, `npm run sim:baseline` (stub-LLM, детерминированно). Адверсариальный аудит подтвердил: все 6 инвариантов целы, тестируется реальный мозг, фаза 0 поведение не изменила.

**Линейка после починки честности** (веса были 30/20/…/attr10; стали **eco35, diag25, bids10, minus10, attr0, anom8, disc7, mem5**; attribution обнулена — group-атрибуция структурно тривиальна: 1 ключ = 1 группа). Калибровка ботов (tuning total): lazy 41 < random 40 < boris 42 < greedy 48 < oracle 72.

**Таблица цикла 1 (после витка 2 — ИСТОРИЯ; текущий скор после Цикла 2.0 + волны аудита — §11 и `sim/SIM_LOG.md`, tuning ~65 / holdout ~64):**

Зазор 0.6 — подгонки нет. Ворота надёжности: 0 срабатываний. Метаморфический пояс: зелёный. Голос Opus по отчётам проверен вручную — отличный (деловой тон, HTML без markdown, цифры точны).

**Принято (виток 2):** диагностика DATA_MISMATCH — Борис сверяет отчёт Директа / Метрику / БД лидов; расхождение ≥2× → «данные, не трафик» (ловит слёт разметки, вал пустышек). Прирост holdout +3.1, ни одна категория не просела.

**Отклонено (виток 1):** гистерезис ставок (4 варианта) — все убивали экономику сильнее, чем поднимали дисциплину. Причина: групповая классификация слишком груба (нужен пофразный экономбиддинг), а симулятор не штрафует болтанку экономически. Мозг откачен.

**Бэклог следующих витков (крупные, требуют владельца):**
1. Пофразный экономический биддинг (заменить групповую классификацию) — чистый путь к дисциплине без потери экономики.
2. Ad-fatigue / learning-reset в движке полигона — чтобы вообще оценивать пользу стабильности ставок.
3. Пофразные Метрика-сигналы (formReachRate по группам) → диагнозы FORM_DROPOFF / AD_TEXT_PROBLEM / BOT_TRAFFIC.
4. Дискриминирующая атрибуция (phrase-level / конвертящая кросс-групповая неоднозначность) → вернуть attribution в тотал.
5. **TOOLS_GAP.md** — карта недоиспользованных инструментов Директа/Метрики (создан этой сессией, на утверждение).

## 7. Контрольные вопросы новой сессии (проверь, что понял)

1. **В каком режиме Борис и как включается боевой?** → OBSERVE — дефолт-предохранитель (нет строки BorisDirectState = observe); LIVE включает только владелец («Борис, боевой»), код сам — никогда. **ТЕКУЩЕЕ состояние — БОЕВОЙ (LIVE) с 06.07** (§11).
2. **Можно ли Борису менять тексты объявлений или добавлять объявления?** → Нет. Объявления — только чтение (`ads.get`). Write по объявлениям вне разрешённого набора; правки текстов — только предложением владельцу.
3. **Что делать с ADD_METRICA_TAG после campaigns.update?** → Вернуть YES (слетает в NO после любого апдейта TextCampaign).
4. **Как Борис ДОБАВЛЯЕТ минус-фразы и как их ОТКАТЫВАЕТ?** → Добавление — ВСЕГДА через единую точку `addNegativeKeywords`: читает СВЕЖИЙ живой список кабинета (`campaigns.get` в момент применения), шлёт ОБЪЕДИНЕНИЕ (живой ∪ новые), fail-safe при непрочтении/подозрительном усыхании → отмена + аномалия. Прямой `campaigns.update(NegativeKeywords)` ЗАМЕЩАЕТ список целиком — звать его напрямую для добавления НЕЛЬЗЯ (стёр бы кабинет). Откат минусов — `removeNegativeKeywords`: удаляет из свежего live ровно `added` (after−before откатанного действия), сохраняя ручные правки владельца; НЕ заливает старый before целиком (merge `9701b08`+`2c972ef`).
5. **По чему агрегируется пофразная экономика (биддинг/защита конвертера)?** → По **CriterionId** (id ключа, на который Директ сматчил запрос) из SQ-отчёта — НЕ по тексту запроса (ключи broad match: реальный запрос ≠ текст ключа). (в) **Гейт недорасхода** (`underspend.ts`: окно 4 рабочих дня, медиана; старт <80% бюджета, вчера ≥95% → мгновенный стоп, гистерезис-полоса) — **пока ТОЛЬКО видимость в отчётах** (строки daily/weekly), ставки не двигает.

**М3.5 — level-lock + ramp-in (`3bf6674`, деплой 10.07).** Повод: 10.07 07:00 на первом тике М3 circuit breaker остановил залп из 93 правок (масс-реплан после смены вердиктов; санити-инварианты ЦЕЛЫ — не баг вердиктов). (а) **level-lock** (`level-lock.ts`): уровень TV фразы фиксируется и меняется ТОЛЬКО при смене Байес-вердикта (не от дрейфа posterior/цен); персист kind `phrase_tv_lock` в `BorisDirectSnapshot` (без миграций); fail-safe — чтение сломалось (throw) → ставки в тик не трогаем. (в) **CB-алерт с СОДЕРЖАНИЕМ** (`formatCbStoppedPlan`: правок вверх/вниз, диапазон Δ, топ по |Δ|) — **немой стоп-алерт запрещён как класс**; строка «ввод портфеля: применено X из Y» в daily. (г) **Маржинальный подъём при недорасходе — МЕХАНИЗМ ГОТОВ, но ВЫКЛЮЧЕН флагом `MARGINAL_UPLIFT_ENABLED=false`.** level-lock убил осцилляцию (с ним при ВКЛ discipline держится 97, в М3 рушилась 96→50), НО эвристика «максимальный TV под E[CPL]-cap 10%» оверштотит уровень → суммарный балл полигона падает. **НЕ включать без решения владельца; включение = отдельный тюнинг-спринт (ретюн выбора уровня на маржинальную отдачу).**

### САГА РЕШЕНИЙ (важно для будущих сессий — почему подъёмы НЕ включены)

Три захода на one тему — «поднимать ли застрявший all-upward хвост / включать ли подъёмы» — и почему каждый честно остановлен:

1. **Сходимость subset→портфельная масса (М3.5-фикс, `725dfbf`).** Ramp-in меряет CB-массу от ПОДМНОЖЕСТВА плана; хотели мерить от всего портфеля, чтобы хвост «пролез». **Дважды отклонено гейтом полигона: economics holdout −7.** Причина (диагностика): сходимость применяет bid-апдейты, которые «следуют за аукционом» и делают заявку дороже; баг ramp-in был СЛУЧАЙНО экономико-защитным. 6 итераций ретюна (единый `chooseTargetLevel` + `E[CPL]≤cap` + raise-gate, TDD) улучшали tuning econ, но переобучались (bids −8 → holdout ниже базы). **Все 6 отклонены** — economics-ретюн уровня НЕ лечит −7, виновные подъёмы окупаемы поодиночке.

2. **Полигон-реализм (`628cb24`) — проверка на ЧЕСТНОМ движке.** Гипотеза: может, −7 был артефактом нечестной калибровки (миры стартовали с оракул-оптимума)? Пересобрали движок под живой факт «28% ниже входа». **ВЕРДИКТ B: сходимость ВРЕДНА и на честном движке** (holdout economics 60.3→49.6). Сходимость закрыта окончательно. Хвост принят на факт (узкое закрытие), будущий биддинг не тронут.

3. **Глобальный never-raise (запрет подъёмов) — НЕ ВНЕСЁН.** На честном движке: holdout **+5.1** / tuning **−2.8** (миры разошлись, живых подтверждений нет). **Решение отложено до ЖИВОГО арбитра** — блока «эффект первой порции» (М5): когорта 39 поднятых 10.07 наберёт вес за ~7 рабочих дней (≈21.07), тогда видно на РЕАЛЬНЫХ данных, окупились подъёмы или нет. Это решение ВЛАДЕЛЬЦА на живых числах, не полигонное.

**Регрессия честности движка (после реализма) ДЕРЖИТСЯ:** оверштот включённого маржинала по-прежнему проседает (tuning −4.4 / holdout −6.0), осцилляция без level-lock рушит discipline 97→41, метаморфика зелёная, trips 0. Движок ловит все известные дефекты — не ослеплён правкой старта.
