## 1. Что за проект и роль

Репозиторий **budni-crm** (Next.js App Router на Vercel, БД Neon + Prisma, Telegram-бот на grammy).
Внутри существующего AI-агента **Бориса** (`src/lib/boris/`) построена НОВАЯ РОЛЬ — **«трафик Яндекс.Директа»** (`src/lib/boris-direct/`). Это НЕ второй бот и НЕ новая личность: Борис один, его личность переиспользуется байт-в-байт.

**North star (дословно от владельца):** «при минимально возможных расходах в рамках цели достичь наибольшего результата с наибольшей эффективностью» = **МАКСИМУМ ЗАЯВОК на рубль** (не клики/охват). Оптимизация на цель Метрики «Заявка».

**Боевые объекты:** кампания `711897777` («Будни — Поиск — Волна 1», ручные ставки HIGHEST_POSITION, Network SERVING_OFF, DailyBudget 3000 ₽); группы G1/G2/G8/G4 = `5769314414..17`; счётчик Метрики `110272989`; цель «Заявка» `575665118`; чат Telegram «Директ от Бориса» `-5284101616`.

## 3. Итог полигона (детали — `sim/README.md`, `sim/SIM_LOG.md`)

Полигон гоняет РЕАЛЬНЫЙ мозг против симулированного мира (мокнут только 6 листовых транспортных модулей; предохранители работают по-настоящему). Прогон: `npm run sim:calibrate`, `npm run sim:baseline` (stub-LLM, детерминированно). Адверсариальный аудит подтвердил: все 6 инвариантов целы, тестируется реальный мозг, фаза 0 поведение не изменила.

**Линейка после починки честности** (веса были 30/20/…/attr10; стали **eco35, diag25, bids10, minus10, attr0, anom8, disc7, mem5**; attribution обнулена — group-атрибуция структурно тривиальна: 1 ключ = 1 группа). Калибровка ботов (tuning total): lazy 41 < random 40 < boris 42 < greedy 48 < oracle 72.

**Финальная таблица (после витка 2, это финальный holdout):**

| категория (вес) | tuning | holdout | зазор |
|---|---|---|---|
| economics (35) | 43 | 45 | +2 |
| diagnosis (25) | 27 | 25 | −2 |
| bids (10) | 62 | 58 | −4 |
| minus (10) | 83 | 83 | 0 |
| anomalies (8) | 39 | 19 | −20 |
| discipline (7) | 9 | 28 | +19 |
| memory (5) | 99 | 96 | −3 |
| attribution (0)* | 100 | 100 | 0 |
| **TOTAL** | **45.0 ± 17.2** | **44.4 ± 13.9** | **0.6** |

Зазор 0.6 — подгонки нет. Ворота надёжности: 0 срабатываний. Метаморфический пояс: зелёный. Голос Opus по отчётам проверен вручную — отличный (деловой тон, HTML без markdown, цифры точны).

**Принято (виток 2):** диагностика DATA_MISMATCH — Борис сверяет отчёт Директа / Метрику / БД лидов; расхождение ≥2× → «данные, не трафик» (ловит слёт разметки, вал пустышек). Прирост holdout +3.1, ни одна категория не просела.

**Отклонено (виток 1):** гистерезис ставок (4 варианта) — все убивали экономику сильнее, чем поднимали дисциплину. Причина: групповая классификация слишком груба (нужен пофразный экономбиддинг), а симулятор не штрафует болтанку экономически. Мозг откачен.

**Бэклог следующих витков (крупные, требуют владельца):**
1. Пофразный экономический биддинг (заменить групповую классификацию) — чистый путь к дисциплине без потери экономики.
2. Ad-fatigue / learning-reset в движке полигона — чтобы вообще оценивать пользу стабильности ставок.
3. Пофразные Метрика-сигналы (formReachRate по группам) → диагнозы FORM_DROPOFF / AD_TEXT_PROBLEM / BOT_TRAFFIC.
4. Дискриминирующая атрибуция (phrase-level / конвертящая кросс-групповая неоднозначность) → вернуть attribution в тотал.
5. **TOOLS_GAP.md** — карта недоиспользованных инструментов Директа/Метрики (создан этой сессией, на утверждение).

## 4. ЖЁСТКИЕ ИНВАРИАНТЫ (нарушение = провал; не трогать даже в тестах)

- **Ветка `boris-direct`.** НЕ мержить в main, в remote НЕ пушить, preview-деплой НЕ запускать до явной команды владельца.
- **Режим OBSERVE по умолчанию** (нет строки `BorisDirectState` в БД = observe). Live включает ТОЛЬКО владелец командой «Борис, боевой». Код live сам не включает никогда.
- **Потолок ставки 400 ₽** (микроединицы 400000000) — предохранитель, не гейт. Живёт в реальном `write-gate` и `rules`, кламп + circuit breaker.
- **Бюджет DailyBudget 3000 ₽ меняет ТОЛЬКО владелец** — Борис предлагает и применяет лишь после явного «да».
- **Аддитивность:** `/api/leads/intake` — `notifyLeads()` не трогать, только запись лида рядом (ошибка записи не ломает Telegram). Существующие модели/кроны/вебхук/роутер колбэков — только добавлять.
- **Личность не форкать** — voice-константы `BORIS_VOICE_BLOCK` и др. в `src/lib/boris/personality.ts` переиспользуются, вывод байт-в-байт.
- **Разрешённый write-набор Директа (ЕДИНСТВЕННЫЙ):** `keywordbids.set` (ставки); `campaigns.update` (NegativeKeywords на верхнем уровне Campaign, DailyBudget, возврат ADD_METRICA_TAG); `keywords.suspend`; `campaigns.suspend` (только аварийно). **Объявления — ТОЛЬКО чтение (`ads.get`), никаких write по объявлениям.** Всё пишущее — только через `write-gate`.
- **Стоп-кран** «Борис, стоп» замораживает всю автономию (перекрывает live).
- **ADD_METRICA_TAG** слетает в NO после любого `campaigns.update` по TextCampaign → после каждого апдейта вернуть YES.
- **Суммы Директа — в микроединицах (×10⁶).** Минус-фразы: без цифр и `/ \ « » "`, слово ≤35 симв (иначе 5002); дубли Яндекс схлопывает (10140 — не ошибка).
- **Секреты только из `process.env`** — не логировать, не коммитить, не выводить в stdout/чат/отчёты.
- **Незнакомую структуру API не угадывать** — предложением владельцу. Новые write-структуры — ТОЛЬКО после пробы на ТЕСТОВОЙ кампании.
- **Миграции — офлайн** (`prisma migrate diff`), к живой БД не применять руками (vercel-build гоняет `migrate deploy` при деплое — поэтому деплой = отдельная команда владельца).
- **Полигон вне прода:** `sim/` не в `src/`, страж-тест `src/lib/boris-direct/sim-boundary.test.ts` запрещает импорт `sim/` из `src/`.
